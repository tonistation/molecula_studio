# Contratos de datos, HTTP y ejecución

**Dos capas distintas:** las ocho operaciones HTTP siguientes existen en `cbfc125`; los contratos de runtime/jobs/adaptadores posteriores son diseño para implementar, no endpoints disponibles ni autorización de ejecución. Datos portables: [schema 1](project-format.md). Confianza, reloj y presupuestos: [arquitectura](architecture.md).

## Autoridad y límites actuales

| Autoridad existente | Responsabilidad |
|---|---|
| `src/shared/schema/types.ts`, `limits.ts`, `parse.ts`, `validate.ts`, `serialize.ts` | Modelo, validación cerrada, límites y wire JSON; no DB |
| `src/shared/digests.ts`, `canonical.ts` | Proyecciones binding-v1 y canonicalización; no firma de autoría |
| `src/companion/store/project-store.ts` → interfaces y métodos públicos | DTO de disco y semántica de operaciones |
| `src/companion/store/receipts.ts` | `SaveReceipt`, `ReceiptVerification` |
| `src/companion/server/http.ts` → `handleApi`, `mapError` | Rutas, headers, cuerpos y estados reales |
| `studio/src/api.ts` → `api`, `ApiError` | Consumidor; duplica algunos tipos de store/receipts, no es segunda autoridad |

No se refactorizan tipos en esta tarea documental. C01 introduce únicamente contratos futuros compartidos; cualquier consolidación de los actuales exige pruebas de compatibilidad y una unidad posterior explícita.

Todo `/api/` exige `Authorization: Bearer <token>` o `x-companion-token`; Bearer reconocido tiene precedencia si está presente. Token efímero de arranque, nunca URL, disco o logs. Host exacto `127.0.0.1:<puerto>` o `localhost:<puerto>`. Origin exacto del companion o de `extraOrigins` explícitos; GET/HEAD pueden omitir Origin, escrituras no (HEAD no es operación API implementada: recibe 405). Sin CORS abierto. No aceptar rutas ni URLs de archivos del cliente. IDs siguen `[a-z][a-z0-9_-]{0,63}`.

Cuerpos JSON: Content-Type que comience por `application/json`; envoltorio ordinario ≤2 MiB +64 KiB. Import/copy ≤6×2 MiB +1024 bytes por expansión de escapes; documento interno sigue ≤2 MiB, profundidad 16. Upload binario ≤50 MiB y MIME exacto (sin parámetros): WAV, MPEG, PNG o JPEG. Límites agregados/inspección: [manifest](project-format.md#manifest-de-activos), `LIMITS` y `media-inspect.ts`. Admisión pasiva de cabecera **no** acredita decodificación audiovisual ni promete componer imágenes; el catálogo visual inicial es procedural.

## Ocho operaciones HTTP implementadas

`p` y `a` representan IDs, no rutas. Los tipos nombrados son los de store/receipts enlazados arriba; los ejemplos de proyecto completos viven en [examples](examples/empty-project.json), no se duplica su schema aquí.

| Operación / consumidor | Solicitud | Éxito y cuerpo |
|---|---|---|
| GET `/api/health` · App/diagnóstico | Sin cuerpo | 200 `{ok:true,name:"molecula-companion",workspace:"authorized"}` |
| GET `/api/projects` · ProjectList | Sin cuerpo | 200 `{projects: ProjectSummary[]}` |
| POST `/api/projects` · ProjectList | `{}` o `{"title":"Proyecto de prueba"}` | 201 `CreateResult`: projectId, project, revision, digest, receipt; crea archivo vacío confirmado, revisión 0 |
| GET `/api/projects/p` · App/Editor | Sin cuerpo | 200 `ReadResult`: project, revision, digest, raw, mode, missingAssets, orphanTemps |
| PUT `/api/projects/p` · Editor | `{project: Project, expectedRevision: number, expectedDigest?: SHA256, operationId: string}` | 200 `SaveResult`: receipt, revision, digest |
| POST `/api/projects/p/copy` · Editor | JSON objeto, normalmente `{text: string, operationId: string}`; opcionales `newProjectId`, `text`, `operationId` | 201 `CopyResult`: projectId nuevo, receipt, revision 0, digest, missingAssets |
| POST `/api/imports` · ProjectList | `{text: string, collision?: "reject"\|"copy"}` | 201 `ImportResult`: projectId, receipt, revision, digest, mode, missingAssets, approvalCleared, importedAsCopy |
| PUT `/api/projects/p/assets/a` · AssetManifest/Editor | Bytes crudos; `Content-Type` MIME permitido. Headers opcionales `x-expected-revision`, `x-expected-digest`, `x-confirm-replace: 1` | 200 `RelinkResult`: projectId, assetId, previousAssetId, replaced, revision, digest, receipt o null, missingAssets, asset |

`ProjectSummary` contiene projectId/title/revision/updatedAt/mode/missingAssets/orphanTemps. En documento inválido el listado usa título/fecha vacíos y revisión −1; listar no certifica apertura válida. `ReadResult.raw` conserva texto leído para descarga sin normalizar en solo lectura. Estilo desconocido admite envoltorio validado y visual inerte, no ejecutar ni editar; schema futuro se rechaza. La ruta HTTP copy puede clonar con identidad nueva y limpiar approval, **no** es un canal de edición del visual desconocido; la descarga del original solo lectura usa `raw` sin cambios.

Copy puede recibir snapshot dirty serializado, con projectId igual al origen, aunque el canónico esté dañado; sin `text` copia disco. Publica staging y activos disponibles, no sobrescribe destino. Import HTTP recibe solo JSON, no carpeta ni binarios: faltantes se revinculan. Sin colisión conserva ID; limpia approval no nula incrementando revisión/fecha; con colisión `copy` crea identidad y revisión 0. Copy siempre revisión 0/fechas nuevas. Conservar IDs de escenas/entities/bindings no acredita vigencia.

Relink restaura bytes iguales sin editar documento (`receipt:null`) o incorpora metadatos/reemplaza mediante commit. Diferente hash exige confirmación, nuevo assetId y actualización de referencias. **Comportamiento actual:** reemplaza la entrada anterior del manifest y, tras recibo confirmed, intenta eliminar su archivo previo (`relinkAsset`, bloque posterior al commit); no hay protección de snapshots históricos implementada. V04b debe retirar esa eliminación automática y proteger revisión/medios previos antes de introducir aprobación audiovisual; no afirmar preservación histórica de bytes como garantía M1. El consumidor envía revisión/digest observados aunque la API los permita opcionales. No existe GET público de activos en esta base.

### Revisiones, digests y recibos existentes

- `digest` de lectura/recibo es SHA-256 de **bytes serializados**, no `approval.contentDigest`. Cambiar whitespace externamente puede provocar conflicto de disco aunque contenido editorial sea igual.
- Editor prepara `project.revision = expectedRevision + 1` y fecha; store valida schema/ID/editabilidad, pero **no comprueba explícitamente esa igualdad** antes de serializar bytes. El recibo calcula expectedRevision+1. Riesgo hallado por inspección estática: cliente arbitrario podría enviar revisión distinta y obtener recibo/archivo inconsistentes; no se reprodujo ni corrigió durante esta tarea documental. C01 debe demostrarlo con test rojo y añadir guard estrecho coordinado antes de nuevos consumidores. Store no autoedita texto ni timestamps. Revisión raíz representa transacción persistida (puede agrupar varias ediciones UI); contador de secuencia dirty permanece solo en memoria. Revisión de escena avanza por cambio de escena. E01/E02 conservan esta separación, sin schema nuevo.
- Exclusión por proyecto cubre comparar/escribir/rename. `expectedDigest` omitido usa último digest observado cuando corresponde; un cliente debe enviarlo para protección explícita entre pestañas. Un companion por workspace, no exclusión universal contra herramientas externas.
- `operationId`: `[A-Za-z0-9][A-Za-z0-9_-]{0,63}` en `store/ids.ts`. Save repite mismo recibo si `(projectId, operationId)` y bytes coinciden; distinto payload →409 conflict/operation. Copy compara fingerprint de snapshot y destino. Tablas de replay son **memoria de proceso**, no garantía de exactly-once tras reiniciar. Create/import/relink no ofrecen idempotencia por operación HTTP. Tras respuesta perdida, releer/listar y reconciliar; no repetir import/create ciegamente.
- `SaveReceipt = {projectId, revision, digest, operationId, committedAt, sync:"confirmed"|"uncertain"}`. 200/201 con uncertain significa rename alcanzado pero flush de directorio fallido. No afirmar rollback ni guardado confirmado: GET y comparación revisión/digest antes de continuar. `verifyReceipt` es método de store, **no novena ruta HTTP**. Un error de verificación posterior tampoco demuestra que no hubo commit. No se promete persistencia física ante corte eléctrico.
- Descarga JSON no llama guardar ni limpia dirty; snapshot editable descargado limpia aprobación según `downloadSnapshot`, original solo lectura usa raw. El servidor no conoce destino ni éxito de descarga.

### Errores actuales

Forma `{error:{code:string,message:string,...details}}`; UI decide por código, no por texto inglés del servidor. `ApiError.status=0` es error local de token/transporte, no estado HTTP.

| Estado | Casos reales / detalles |
|---|---|
| 400 | invalid-json, empty-body, invalid-argument, IDs inválidos, unsafe-path sanitizado |
| 401 | unauthorized, token ausente/inválido |
| 403 | host-not-allowed, origin-required, origin-not-allowed |
| 404 | not-found, project-not-found, asset-not-found (+assetId) |
| 405 | method-not-allowed y header Allow |
| 409 | conflict (+reason revision/digest/operation/asset-content), project-exists, read-only-project, workspace-locked |
| 413 | body-too-large; asset-rejected/too-large |
| 415 | unsupported-media-type; asset-rejected/mime-mismatch |
| 422 | invalid-project (+failure/issues), demás asset-rejected (+reason: límites/cabecera/timeout/ocupación) |
| 500 | commit-failed, commit-verification-failed, otros StoreError/internal-error |

Static de estudio no es API: GET/HEAD, no-store, nosniff, CSP e inyección de token en HTML; 503 studio-missing si no hay build. No atribuir SSE, WebSocket, DELETE, ruta de recibos o streaming de medios a esta implementación.

### Evaluación y catálogo

`evaluateVisual(snapshot: Project, frameIndex: number): EvaluatedFrame` es pura sobre V01. Resultado `{sample:FrameSample,camera:{position:Vec3,target:Vec3,fovDeg:number},instances:EvaluatedInstance[],overlays:Overlay[],word:Word|null}`. Instance: `{componentId,entityId,definitionVersion,position:Vec3,rotation:Vec3,scale:number,opacity:number,pose:{sway:number}}`; no geometría/material mutable ni referencias al snapshot. Overlay: `{id,kind:"label"|"caption",text,color,anchor:"upper"|"center"|"lower",emphasis:boolean}`; posición de label proyectada por el runtime desde su entidad, no coordenadas CSS libres importadas.

`StyleRegistry.resolve(id,version)` devuelve `{id,version,validate,createDefinition,createInstance,dispose}` o error `style-unavailable`; solo `stylized-3d@1`, procedural-v1@1. Definitions cache por hash de identidad/version/seed/generador; instances poseen material/rig mutable, dispose idempotente. PRNG indexado **no criptográfico**, síncrono/isomorfo: codificar UTF-8 del JSON canónico `{seed,entityId,generatorVersion,channel,index}`; FNV-1a uint32 inicia 2166136261 y por byte `h = imul(h ^ byte,16777619) >>> 0`. Avalanche final: `h ^= h >>> 16; h = imul(h,0x7feb352d); h ^= h >>> 15; h = imul(h,0x846ca68b); h ^= h >>> 16`; resultado `(h >>> 0) / 4294967296`. `imul` es Math.imul, no multiplicación flotante libre. Canales cerrados por generador; para variación por instancia añadir sceneId/componentId al canal construido por código, nunca por archivo. No se usa este hash para seguridad/bindings (siguen SHA-256). No Math.random/fecha/deltas. Interpolación/movimientos existentes en formato son autoridad; interpolación inválida (position=target) falla `camera-degenerate`, no ajuste silencioso.

### Runtime y readiness

`CompositionRuntime.prepare({snapshot:Project,snapshotId:string,rendererVersion:string,assets:AssetDescriptor[]}, signal): Promise<PreparedRuntime>` valida estilo y verifica fuente/activos; asset descriptor `{assetId:string,sha256:string,byteLength:number,mimeType:AssetMimeType,resourceId:string}` sin ruta absoluta. `PreparedRuntime.renderFrame(frameIndex:number,requestId:string): Promise<FrameReady>`; `FrameReady={snapshotId:string,requestId:string,frameIndex:number,stateDigest:string,rendererVersion:string,width:1080,height:1920}`. `dispose():Promise<void>` idempotente. Solo una llamada en vuelo por runtime, segunda →`runtime-busy`; snapshot inmutable hasta dispose. Readiness significa carga/decodificación completada, fonts.ready, evaluación aplicada, render WebGL y DOM/SVG estabilizados, no solo requestAnimationFrame; verificar vía captura que no publica frame anterior. Fallos: invalid-snapshot, asset-unavailable, asset-hash-mismatch, font-unavailable, prepare-timeout, frame-timeout, runtime-disposed. RequestId/frame deben coincidir antes de screenshot de raíz completa.

Rutas privadas **propuestas V05a**: GET `/internal/render/sessions/:sessionId` para página, GET `/internal/render/sessions/:sessionId/resources/:resourceId` para bytes verificados. Worker obtiene snapshot de su repositorio por ID y llama `prepare`/`renderFrame` por `page.evaluate` sobre bridge empaquetado y validado; **no existen rutas HTTP prepare/frame** ni eval de cadenas del proyecto. Bridge admite solo esos DTO/métodos y dispose, sin filesystem, comandos ni credenciales. Sesión generada por servidor, vinculada a propósito preview/capture, snapshotId, jobId o null y TTL; capture se cierra al terminar. Negar sesiones ajenas/caducadas (404), sin token (401), origen/Host ajeno (403), métodos (405). Errores del bridge son códigos runtime, no estados HTTP inventados. HTTP privado conserva **token efímero y Origin/Host estrictos**; header en navegación/recursos del worker, nunca token en URL ni snapshot. ResourceId se resuelve en mapa del servidor. Red permitida solo runtime empaquetado/recursos de sesión; sin acceso genérico a workspace, HTML importado, proveedores ni file://.

Para preview integrado, V05a añade POST autenticado `/api/projects/:id/preview-sessions` con `{project:Project,expectedDigest:string}` y límites JSON actuales →201 `PreviewSession={sessionId:string,snapshotId:string,rendererVersion:string,assets:AssetDescriptor[],expiresAt:string}`. Valida draft sin exigir aprobación editorial, projectId y base de disco coincidentes; solo recursos manifest del workspace autorizado verificados, nunca paths del cliente. Devuelve 409 si base cambió, 422 si draft/recursos consumidos incompatibles; fuente/estilo ausente se muestra como fallo de preparación. Un preview vivo por proyecto, nueva sesión reemplaza la anterior de ese proyecto tras liberar recursos; expira después de 10 min inactivo, se recrea por acción. Dirty snapshot vive solo en sesión temporal acotada, no se guarda ni se aprueba; audio/words obsoletos no se reproducen como actuales. V03 prueba fixture mediante resolvedor cerrado local del harness, no promete aún esta ruta de medios. D01 controla fuente real.

### Preflight, trabajos y publicación

Diseño V06: POST `/api/projects/:id/preflight` recibe `{expectedRevision,expectedDigest,options:{voiceMode, captionsEnabled}}`; responde 200 `{snapshotId,projectRevision,fileDigest,contentDigest,options,checks:PreflightCheck[],ready:boolean}`. Check `{code,level:"error"|"warning",sceneId?:string,assetId?:string,action:"save"|"review"|"relink"|"diagnose"|"none"}`. No lanzar job ni aprobar. SnapshotId expira tras 10 min si no se consume/protege; petición con opciones distintas del documento guardado →409 output-options-changed, requiere editar/aprobar/guardar. Checks: saved, editable-style, visuals, font, assets, bindings, approval, audio-fit, runtime, disk, capacity. Solo medios consumidos; silent ignora audio faltante/obsoleto pero timings de palabras deben corresponder a silent. V05 puede probar pipeline directamente sin esta ruta; no certificar exportación de producto antes de V06.

POST `/api/projects/:id/jobs` `{operationId,snapshotId,expectedDigest}` →202 `{job:Job}`; snapshot aprobado/inmutable y espacio reservado; repetición mismo operationId+entrada devuelve mismo job, diferencia →409 operation-conflict. Revalidar activos/capacidad dentro de lock, no confiar en preflight viejo. GET `/api/projects/:id/jobs` →200 `{jobs:Job[]}`; GET `.../jobs/:jobId` →200 `{job:Job}`; POST `.../jobs/:jobId/cancel` `{}` →202 `{job:Job}` (terminal:200, sin relanzar). GET `.../results/:resultId` →200 MP4 verificado con content-length/hash, sin ruta local ni shell abrir. Resultado ausente 404; no publicar parcial. Polling 500 ms mientras activo, pausa con pestaña oculta; sin SSE requerido.

`Job={jobId,attemptId,operationId,operationKey,projectId,projectRevision,snapshotId,inputDigest,sceneRevisions:Record<string,number>,status,stage:"queued"|"prepare"|"capture"|"encode"|"verify"|"done",progress:{completedFrames,totalFrames},resultState:"current"|"stale",resultId:string|null,errorCode:string|null,createdAt,updatedAt}`. Status exactamente los seis de PRD; cancelando es estado de solicitud visible hasta confirmación de terminal. Intento nuevo tiene IDs nuevos y temporales distintos; repetición de envío no es reintento. Terminal monotónico, transición a succeeded solo después de verificar y publicar. Un escritor de journal por companion; una tarea activa y dos en cola, cancel/complete serializados por job. Al reinicio queued/running →interrupted, nunca relanzar.

`ExportReceipt={resultId,jobId,attemptId,projectId,projectRevision,contentDigest,inputDigest,rendererVersion,browserVersion,fontHashes:Record<string,string>,voiceMode,captionsEnabled,assets:{assetId,sha256}[],mp4Sha256,byteLength,width:1080,height:1920,fps:30,durationMs,createdAt}`. Registro fuera de project.json. Current se deriva comparando contenido/opciones/activos y existencia/hash del MP4, no solo revisión raíz o estado succeeded. Render de snapshot anterior puede finalizar stale sin tocar borrador. Encoder produce H.264 y AAC cuando withVoice; silent sin pista de audio, duración exacta y frames esperados verificados antes de rename de publicación. Audio se completa con silencio, nunca se estira/recorta implícitamente. Error codes adicionales: preflight-blocked (422 con checks), snapshot-expired (409), queue-full/retention-full (409), insufficient-disk (422), job-not-found (404), worker-crashed/encoder-failed/verification-failed/watchdog-limit (job failed, no falso 200 de resultado). Heredar 400/401/403/405/413 de frontera actual.

Tipos de campos sin anotación en estas formas cerradas: IDs/digests/versiones/fechas/errorCode son string; revisiones/bytes/ms/frames son number enteros seguros no negativos; flags son boolean. Nullable solo donde se escribe null. `inputDigest` de export = SHA-256 canónico de `{contentDigest,voiceMode,captionsEnabled,assets,fontHashes,rendererVersion,browserVersion}` con assets ordenados por assetId y hashes verificados; `operationKey` = hash de `{kind:"export",inputDigest}`. `stateDigest` = hash de EvaluatedFrame, sin objetos engine. No reutilizar fileDigest como digest editorial. Límites a strings/IDs/versiones y arrays de DTO heredan schema/PRD; journal de metadatos ≤16 KiB/entrada, diagnóstico sin contenido. Campos no reconocidos se rechazan.

### Retención local acotada — diseño V06/E06

V04b inicia la protección mínima de aprobaciones/medios antes de consumidores audiovisuales; V06/E06 la amplían a jobs/propuestas. Las cuotas retenidas siguientes **incluyen medios históricos que permanezcan en assets/** aunque ya no estén en manifest. Los activos actuales mantienen además el límite de 500 MiB; no esconder consumo histórico fuera del cómputo ni eliminarlo por ausencia en manifest.

Directorio propuesto `<workspace>/.studio-runtime/`, no portable ni servido estáticamente: snapshots canónicos, journal de metadatos, proposals y results por IDs. Nunca guion completo/credenciales en journal ni diagnóstico; snapshot separado sí contiene contenido local necesario para preservar revisión anterior. Escrituras atómicas; leer entradas acotadas y rechazar symlinks. Exportaciones portable/manuales no se consideran current sin recibo verificable.

**Propiedad secuencial propuesta:** V04b crea `src/companion/store/snapshot-repository.ts`, repositorio companion de disco compartido, no módulo isomorfo/UI. Su interfaz interna `SnapshotRepository` expone `retain(project:Project,fileDigest:string,owner:SnapshotOwner):Promise<SnapshotRef>`, `read(projectId:string,snapshotId:string):Promise<Project>`, `pin(projectId:string,snapshotId:string,owner:SnapshotOwner):Promise<void>` y `release(projectId:string,snapshotId:string,owner:SnapshotOwner):Promise<void>`. `SnapshotOwner={kind:"approval"|"job"|"proposal",id:string}`; `SnapshotRef={projectId:string,snapshotId:string,fileDigest:string,contentDigest:string}`. Retain valida/copia snapshot y medios verificados con reserva/comprobación de cuota bajo lock antes de publicar; owner repetido para mismo contenido es idempotente, para otro contenido falla conflicto. Read valida hashes y devuelve copia sin referencias mutables; pin protege la misma evidencia sin duplicar repositorio; release retira solo ese pin, **no elimina bytes** ni otros owners. Rutas y presupuesto son internos, nunca argumentos de navegador. Errores: retention-full, snapshot-not-found, snapshot-hash-mismatch y unsafe-path. V04b prueba owner approval/medios históricos; V06b consume la misma interfaz desde `src/companion/jobs/snapshots.ts` como adaptador de jobs/pins/reservas de salida, sin segunda implementación de disco. Extensiones necesarias se integran secuencialmente por coordinador tras cierre de V04b, manteniendo sus oráculos y contrato.

Default técnico: 1 GiB para snapshot/propuestas/resultados retenidos por proyecto y 4 GiB por workspace; temporales activos adicionales ≤2 GiB/job con 3 GiB libres previos como arquitectura. Salida MP4 máximo 256 MiB y propuesta máximo declarado en RequestPreview (voz ≤50 MiB por archivo); reservar ese máximo antes de empezar, abortar al exceder sin publicar/truncar como éxito. Hasta 20 intentos terminales no protegidos por proyecto, 7 días de metadatos no protegidos. Cache recreable de geometría/frames máximo 128 MiB por runtime, LRU; eliminar cache nunca elimina evidencia. Proteger (sin TTL automático) snapshots/activos de jobs vivos, última aprobación y aprobaciones anteriores con medios/resultados retenidos, último resultado verificado, propuestas no revisadas (incluso tardías) y medios históricos referenciados por cualquiera de ellos o por proyecto. No borrar activos de `assets/` automáticamente en v0.1. Purga automática solo cache y metadatos no protegidos; otros artefactos requieren selección explícita con referencias/efecto mostrados. Si no cabe nueva reserva, rechazar **antes** de ejecutar (`retention-full`), no desalojar evidencia protegida. Si proveedor excede límite, registrar fallo y no reintentar. Una aprobación nueva no destruye snapshot anterior. Copia/importación no transporta journal ni historial y lo advierte. Sin historial ilimitado, DB ni nueva clave en schema 1.

### Adaptadores y propuestas — diseño E03/E04/E06

`Capability="script"|"voice"`. `Adapter.describe()` → `{adapterId,version,capability,mode:"fake"|"real",supportsIdempotency:boolean,timestampUnit:"ms"|"seconds"|"none",limits:{maxInputChars,maxOutputBytes},cost:{currency:string|null,estimatedMax:number|null}}`.

`prepare({snapshotId:string,sceneIds:string[],capability:Capability,adapterId:string}):Promise<RequestPreview>` → `RequestPreview={requestId:string,inputDigest:string,snapshotId:string,sceneIds:string[],capability:Capability,adapterId:string,adapterVersion:string,payloadSummary:string,estimatedCost:number|null,currency:string|null,maxOutputBytes:number,expiresAt:string}`. Costo estimado es cota máxima no negativa o null, no garantía de factura. PayloadSummary es texto plano visible, no va al journal; la UI permite inspeccionar campos exactos a enviar desde snapshot local. Preview no llama proveedor, no lee secretos ni es aprobación. TTL 10 min, una operación activa global. Script limita 12 escenas/12000 caracteres y respuesta ≤2 MiB; voz ≤50 MiB/archivo, ≤500 MiB/proyecto y tiempos de schema. Parámetros de proveedor quedan fuera del JSON, seleccionados de allowlist de adaptador, incluidos en inputDigest de solicitud: hash canónico de `{capability,adapterId,adapterVersion,sceneInputs,parameters}`; sceneInputs ordenados por orden narrativo e incluyen sceneId/text/locale y hashes de medios efectivamente enviados, nunca secretos.

`execute(preview, {authorizationId,attemptId,idempotencyKey?:string}, signal)` → `Proposal`. Credencial de sesión se resuelve en companion, nunca en DTO de UI/runtime. AuthorizationId de un solo uso, ligado a requestId/inputDigest/capacidad/proveedor/presupuesto y confirmación explícita; fake se etiqueta sin red/costo, real requiere gate D04 aparte. Timeout después de envío →`remote-uncertain`, sin retry automático aunque se aborte. Resultado incierto conserva attemptId y revisión origen. Método opcional `reconcile(attemptId,signal)` solo si servicio documenta consulta segura; no reenviar execute para consultar.

`Proposal={proposalId,attemptId,snapshotId,inputDigest,sceneRevisions,capability,adapterId,status:"ready"|"rejected"|"accepted"|"failed"|"remote-uncertain",resultState:"current"|"stale",payload:ScriptProposal|VoiceProposal|null,errorCode:string|null}`. Script payload `{scenes:{sceneId:string|null,title,text,visualIntent,durationMs}[]}` se valida/cierra antes de revisión; no código/HTML ni geometría arbitraria. Voice payload `{sceneId,resourceId,mimeType,sha256,byteLength,durationMs,words:Word[]}` refiere staging acotado, no URL/ruta remota. Conversión seconds→ms: redondeo al ms más cercano una vez, luego validar límites/orden y no solapamiento; si colapsan palabras se rechaza, no se corrigen. Proveniencia/licencia se revisa antes de incorporar al manifest.

`GenerationAttempt={attemptId:string,requestId:string,operationId:string,snapshotId:string,inputDigest:string,status:"queued"|"running"|"succeeded"|"failed"|"cancelled"|"interrupted",remoteState:"not-sent"|"sent"|"known"|"uncertain",proposalId:string|null,errorCode:string|null,createdAt:string,updatedAt:string}`. Proposal se crea al disponer de resultado validable o al registrar incertidumbre; no fingir propuesta lista mientras execute sigue pendiente. Terminal no se reabre; reconcile añade evidencia sin reenviar ejecución. OperationId+inputDigest repetidos devuelven mismo intento desde journal, diferencia rechaza conflicto.

Rutas **futuras** E04/E06 bajo `/api/projects/:id`: POST `/requests/prepare` con campos de prepare →200 preview; POST `/requests/:requestId/authorize` `{inputDigest,confirmed:true,budgetLimit:number|null}` →201 `{authorizationId}`; POST `/requests/:requestId/execute` `{authorizationId,operationId}` →202 `{attempt:GenerationAttempt}`; GET `/attempts/:attemptId` →200 `{attempt:GenerationAttempt}`; POST `/attempts/:attemptId/cancel` `{}` →202 intento mientras se detiene o 200 si terminal; GET `/proposals/:proposalId` →200 proposal; POST `/proposals/:proposalId/accept` `{expectedRevision,expectedDigest}` →200 `{proposal:Proposal,save:SaveResult}` o `/reject` `{}` →200 `{proposal:Proposal}`. BudgetLimit para real debe ser número máximo explícito en moneda del preview, compatible con gate D04; costo desconocido exige advertencia y tope autorizado, no ejecución ilimitada por null. Fake admite null sin cobro. Aceptar es CAS dentro del lock, actualiza solo destinos revisados y bindings exactos; edición concurrente →409 stale-proposal, no aplicar forzado. Revisión actual de esquema y límites antes del commit; UI puede inspeccionar stale, pero debe preparar revisión nueva/manual explícita, nunca botón que ignore digest. Cancel no garantiza anular cobro. Errores: adapter-unavailable (422), approval-required/authorization-expired/consumed/request-changed/stale-proposal (409), invalid-provider-response/remote-uncertain (error del intento/propuesta), retention-full (409), IDs ausentes (404). Frontera hereda 400/401/403/405/413. Nunca guardar secreto/headers/cuerpo remoto íntegro en error. E03 prueba métodos internos fake; rutas/revisión humana se entregan después en E04/E06.

### Descubrimiento de intentos y propuestas tras reinicio — diseño E06

El índice de descubrimiento se reconstruye desde journal/metadatos locales persistidos, nunca desde memoria de UI. Publicar una propuesta y su enlace de intento debe ser atómico o reconciliable localmente: no anunciar propuesta retenida disponible sin enlace durable; tras crash, validar/reconciliar archivos propios contra snapshot y journal sin proveedor. Staging incierto se conserva/señala, no se borra ni se promociona silenciosamente. Esto no añade historial al JSON ni cambia cuotas o política de protección.

Los GET por ID no bastan cuando se perdió la memoria del navegador. E06a añade GET autenticado `/api/projects/:id/attempts?limit=20&cursor=<cursor>` →200 `{attempts:GenerationAttemptSummary[],nextCursor:string|null}`. `GenerationAttemptSummary` es la proyección cerrada de GenerationAttempt con `attemptId`, `proposalId` (string o null), `snapshotId`, `status`, `remoteState`, `errorCode`, `createdAt` y `updatedAt`, con los mismos tipos. No incluye guion, credencial, payload de propuesta ni ruta. Cada proposal retenida conserva su fila mínima de intento y enlace proposalId; no purgar esa fila mientras la propuesta esté protegida, aunque exceda 20 terminales o tenga más de 7 días. ProposalId no nulo conduce al GET de propuesta del mismo proyecto; un ID de otro proyecto devuelve 404. Leer o listar nunca acepta, ejecuta ni reenvía solicitudes.

`limit` entero 1–50, default 20; cursor opcional opaco ≤512 caracteres, firmado por sesión y ligado a proyecto, corte y última posición; datos inválidos/manipulados/proyecto incorrecto →400 invalid-cursor o invalid-argument. Origin/Host/token, no-store y demás errores de frontera se conservan; proyecto inexistente →404. Orden descendente por secuencia monotónica de inserción del journal, privada y persistida (no un campo nuevo de project.json). La primera página fija un corte de secuencia; páginas siguientes usan keyset hasta nextCursor null, sin offsets ni escaneo/retorno ilimitado. Estados y proposalId se leen vigentes al consultar; el corte estabiliza pertenencia/orden, no congela sus actualizaciones. Intentos insertados después del corte aparecen al refrescar desde primera página. TTL del cursor 10 min; caducidad o reinicio del companion →409 cursor-expired, reiniciar paginación desde proyecto, no depender de recordar cursor/attemptId/proposalId. El cursor no es credencial ni autoriza acceso sin token.

Una sesión de navegador totalmente nueva obtiene token actual desde el companion, lista/abre el proyecto mediante API M1 y recorre estas páginas para recuperar intentos/proposalIds retenidos desde disco. Tras reinicio del companion, queued/running pasan a interrupted; si hubo envío sin resultado confirmado, remoteState permanece/pasa a uncertain, nunca known inventado. Si hay propuesta tardía conservada se recupera con el ID descubierto; si no hay resultado, se muestra incertidumbre/interrupción sin fabricar propuesta ready. Retención protegida y cuotas existentes siguen aplicando: no evicción silenciosa para acortar listado. **Ni arranque, ni descubrimiento, ni GET, ni refresco disparan proveedor, reanudación, reconcile remoto o retry.** Consultar un proveedor para reconciliar requiere acción/autorización aplicable; reintentar sigue exigiendo intento/autorización nuevos explícitos. Oráculos red-first de E06a/E06b prueban recuperación sin IDs recordados, disco/procesos reales y cero nuevos envíos.

## Aprobación editorial única

Una sola `project.approval` sobre **todo** contentDigest. No hay sellos parciales de guion/visual/voz en schema 1. Revisiones por panel y aceptación de bindings son pasos de revisión, no aprobaciones editoriales independientes. La fixture M2 usa la misma regla que M3, con UI mínima, no una excepción al preflight. Ver [vínculos y aprobación](project-format.md#vínculos-portables-y-aprobación-editorial). Ni ese sello ni authorize sustituyen permiso externo para habilitar proveedor/presupuesto.

## Ingesta manual de medios nuevos — diseño E01c

Relink actual exige assetId ya declarado; no basta para «Importar audio» nuevo en P3. No presentar ese botón como implementado. Diseñar POST `/api/projects/:id/asset-ingestions`: bytes crudos con los mismos cuatro MIME/límite 50 MiB e inspección actual; headers **obligatorios** `x-expected-revision`, `x-expected-digest`, `x-asset-license` y opcional `x-asset-attribution`. Los dos últimos contienen texto UTF-8 percent-encoded por encodeURIComponent, acotados a 12 KiB combinados de header antes de decodificar y a límites Asset.source después; percent inválido/control/NUL →400, sin interpretar URLs. No admitir source.origin del cliente: manual fija `user`. No nombre/ruta de destino ni bytes base64 JSON. UI exige guardar o cancelar antes de subir si hay dirty; esta operación modifica canónico, no fusiona draft arbitrario.

Companion genera ID/ruta, inspecciona/copia/hash en staging acotado y dentro del lock compara base antes de publicar archivo/manifest. Archivo queda disponible antes de commit JSON, nunca referencia confirmada a un archivo aún incompleto; fallo precommit conserva JSON y limpia solo staging propio, fallo tras publicación/commit se reconcilia por recibo/GET sin retry ciego. No borrar otros medios. Respuesta 201 `AssetIngestionResult={asset:Asset,revision:number,digest:string,receipt:SaveReceipt}`; errores actuales de asset, 409 CAS, 413 exceso, 422 capacidad o procedencia ausente. No idempotencia prometida: tras respuesta perdida listar/releer manifest y comparar hashes antes de repetir.

Agregar manifest no selecciona audio ni acepta bindings. Elegir su uso por escena es acción editorial posterior E01b/E02; deseleccionar conserva archivo, audio existente y medios históricos nunca se sustituyen por ID. PNG/JPEG admitidos para portabilidad/recurso, no nueva capacidad de composición. E04b puede reutilizar servicio interno de ingesta con procedencia provider revisada, pero no aceptar paths/URLs remotas como recurso. No requiere DB ni cambio de schema 1.
